# VOGPK Admin

Independent Next.js application, JavaScript/JSX, port 3001. This is the staff application; the customer storefront stays in `frontend`.

For the separate `vogpk-admin` Vercel project, see [production setup and prerequisites](../docs/admin-vercel-deployment.md). No admin hosting project has been created by this update.

On the separate admin hostname, `/` sends logged-out visitors to `/login` and verified sessions to `/dashboard`. The customer storefront homepage stays public at port 3000. Protected admin destinations are preserved through validated relative `returnTo` links. See [Netlify/domain and routing setup](../docs/admin-routing-netlify.md).

Read [Phase 1 setup and security documentation](../docs/admin-phase1.md) before starting. Configure the backend, migrate and seed its database, and supply matching server-only environment settings. There is no public signup, default password, fake login or owner account automatically created by installation.

```powershell
npm ci
npm run dev
```

Production checks: `npm run lint`, `npm run build`, `npm start`.

Vercel Preview builds (`VERCEL=1`, `VERCEL_ENV=preview`) derive their HTTPS origin from the platform's `VERCEL_URL` hostname. With no isolated configuration they build a preview notice: no sign-in form, session/CSRF cookies, backend requests or privileged API operations. Protected pages redirect to the notice, and auth/BFF endpoints return no-store 503 responses. The ordinary Production variables are ignored in this mode; Production validation and cookie names are unchanged.

Optional Preview authentication requires an explicit `PREVIEW_AUTH_ENABLED=true` plus server-only `PREVIEW_API_URL`, `PREVIEW_STOREFRONT_ORIGIN` and `PREVIEW_BFF_SHARED_SECRET`. Configure these only for an approved, separate backend/database and secret. Full HTTPS/origin/secret checks still apply, cookies use a separate Preview namespace, and known Production API/secret reuse is rejected. The isolated backend must accept the exact generated deployment origin; use that deployment URL for sign-in rather than an unconfigured alias. The app cannot independently attest the remote database's isolation. No Preview credentials or backend are provisioned by this change.

`npm run test:preview` checks configuration isolation and builds a clean fixture with none of the six runtime variables, then probes the real Next server. It verifies protected pages and API operations stay blocked, no auth cookies are issued and no request reaches a local backend trap even when normal runtime variables and forged cookies are supplied. It also verifies Production still rejects missing configuration. This is fail-closed Preview verification, not a claim that isolated Preview authentication was provisioned or logged in.

`npm run test:routing` verifies return-path and environment safeguards. `npm run build` first validates deployment URLs and cookie settings. Local built-app testing requires `ADMIN_ENVIRONMENT=local`; hosted deployments require exact HTTPS origins. `admin/netlify.toml` is prepared for a Netlify project with Base/Package directory `admin`; no SPA fallback or static export is used.

Browser verification: with the isolated test API from the backend security suite running on port 4000, run `node scripts/test-admin-browser.cjs`. Playwright may be supplied through `PLAYWRIGHT_MODULE`. Test accounts are generated by the backend suite and live only in its separate local test database; they are never the development owner.

For verification against the **unchanged normal development API**, use the guarded `backend` command `npm run verify:dev:provision`, then `npm run test:auth:development` here. This uses real development principals, a Windows-user DPAPI vault and automatic session/account cleanup, with no API_URL override. See [the completed real authentication report](../docs/admin-auth-verification.md) before repeating it.

After converting the verification owner to an operational local account, the old verification vault is intentionally stale. These verification commands refuse to overwrite that owner. Do not reset the operational password or copy it into a test vault to repeat the original fixture run. The commit audit separately verified real owner login, protected routes, refresh, CSRF and logout using the approved development API; see `docs/commit-auth-verification.json`.
